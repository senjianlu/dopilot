# rawf-implement:实现阶段

## 前置检查

1. 读 `.ai/.current-task` 定位任务目录;读 plan.md,确认 `status: approved`。
   不是 approved → 停,回到 /rawf-plan 的确认闸,不要试图绕过。
2. 计算轮次:NN = 目录中已有 implementation-round-*.md 数量 + 1(两位数)。
   修复轮上限:取 plan.md frontmatter 的 `impl_fix_max_rounds`;字段缺失
   或非正整数一律按**默认 3**。该字段仅当用户明确要求放宽时写入,不得
   自行添加。若 NN > 上限:停止实现,向用户说明已达修复轮上限,交人工判断。

## 实现

3. 第 1 轮:按 plan 实现;动手前若本任务跑过 plan 评审,先运行
   `bash .ai-workflow/scripts/plan-review.sh __minors <任务目录>` 汇总**全部
   轮次**的 plan 评审 minor(不只最后一轮——收敛轮降级的问题也在其中),在
   implementation-round-01 的「plan 评审 minor 交接」节逐条写处置。
   第 2 轮起:只修 review-round-<上一轮>-fail.md 中的
   blocker 与 major,逐项对应;不顺手重构无关代码,评审范围外的"改进"会
   污染下一轮 diff。
4. 与 plan 的任何偏差都必须记入产物的"与方案的偏差"表,类型只有三种:
   **收窄**(少做/范围缩小)、**替代**(同一目标换做法)、**追加**(plan
   范围之外新增的文件、行为或功能)。收窄与替代如实记录即可;偏差若动到
   方案的核心(架构、接口),先停下来问用户。**追加类不得自行实现**:要么
   停下问用户、经确认后再做(处置栏注明确认时间),要么不做、写进「停车场」
   留给后续任务。"只加强不放宽""顺手修一下"都不是自授权理由——范围核对
   是评审的固定问题,未声明的范围外改动会被列出交用户裁决。

## 自测

5. 逐条执行 plan.md 的全部测试用例,**按 plan 声明的档位**记录真实结果与
   证据(档位定义见 review-standards.md「测试证据档位」):
   - **A 档**:一律用 `bash .ai-workflow/scripts/evidence.sh TC-NN [-l 标签]
     -- <命令...>` 留证,产出 `evidence/TC-NN.log`(rawf-evidence v1:命令 +
     完整原始输出 + 退出码;同名已存在则拒绝覆盖,重跑加 `-l`)。按 plan
     证据形态列的写法包命令:(a) 直接包被测命令,或 (b) 包断言脚本。
     不得手工拼写证据文件、不得截断输出。评审进行中不得运行(evidence/
     计入指纹);
   - **B 档**:给出 `文件:行号` 或日志片段,须真实存在且支持结论;
   - **C 档**:给出结果陈述 + 关键锚点;评审默认采信,不会仅因无原始命令
     输出而打回。
   截图等其他证据同样落 `evidence/`(且不得作为任一用例的唯一证据);引用
   的素材(Design 稿、参考图)放 `assets/`。以上均须在**评审前**落盘——
   `.ai/` 计入 review.sh 指纹,评审进行中写入会使评审无效(见 CLAUDE.md
   硬规则)。
6. 实事求是,以下为硬规则:
   - **不得下调** plan 已声明的档位,**不得改写**用例的重要性或预期结果。
     实测发现某用例无法按原档位执行 → 结果记 `blocked`,**停下向用户说明**,
     由用户决定改 plan 还是接受降档;不得自行降档后照常送审。
   - **唯一例外:机械性更正**。用例中意图明确的机械性错误(笔误、排序、转义、
     算术)按意图更正,处理方式唯一:① **回写 plan 测试表**,在原单元格内就地
     更正并追加标注 `〔机械性更正:原文「…」;理由:…;见实现记录 D-NN〕`
     (不新增 `|`,保持表格可被 evidence-check 解析);② 实现记录偏差表记
     "替代",写明原文、更正后文字与理由。实现评审以更正后的文字为基准,并
     核验更正是否越界。改变用例意图、删减场景或放宽断言都不属于机械性更正 →
     停下问用户。
   - **禁止虚构或推测测试结果**。未执行写"未执行"+原因,失败写失败——
     评审者在只读沙箱中**不重跑任何测试**(review-standards.md「评审动作
     边界」),测试真实性完全靠证据核验,虚报通过在评审中是 blocker 级问题。
   - 存在 `blocked` 项时**不进入评审**,须先经用户裁决。
7. 全部用例通过之前不进入评审;反复修不过,向用户说明卡点。

## 产物与交接

8. 按 .ai-workflow/templates/implementation-round.md 写
   implementation-round-<NN>.md 到任务目录;测试结果表每条 plan 用例一行,
   编号与档位照抄 plan;A 档证据栏写 evidence.sh 产出的文件名;偏差表与
   停车场按模板填写(没有写"无")。
9. 写完先自跑 `bash .ai-workflow/scripts/evidence-check.sh`:它以 plan 用例表
   为基准核对记录(漏行、档位不符、空表、blocked)与每个 A 档证据文件的
   结构完整性;不通过按补交清单补齐后再跑,通过才进入 /rawf-review
   (review.sh 启动前会再跑一次,不通过直接拒绝启动、不消耗评审轮次)。
   通过后直接进入 /rawf-review,无需用户确认(评审不改代码)。
