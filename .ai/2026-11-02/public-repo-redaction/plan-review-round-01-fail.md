# Plan 评审:第 01 轮

## 问题清单
- [major] R-01 “全部 git 历史”的引用范围与发布策略未定义。
  - 详情:定位：plan.md:31、60、70、107–120。方案以 master 的 67 个提交描述历史，但当前仓库 --all 可达 95 个提交，另有分支、backup/pre-normalize 标签及 refs/original；执行阶段却只 fetch、reset、强推 master。未明确 export、verify、check --history 各自遍历哪些 refs，也未证明远端公开引用仅有 master，因此无法据此保证全部公开历史脱敏。请定义引用清单、各引用的处理或排除理由及发布后核验范围；增加合成分支和标签用例，验证范围内引用全部指向脱敏历史。私有备份引用可以明确排除，无须删除。
- [major] R-02 历史完整性核验仅检查 tip，可能漏过中间提交的数据损坏。
  - 详情:定位：plan.md:70、174、177。verify 对文件路径和内容仅比对 tip；提交数、父子结构、作者一致及全历史零命中，均不能证明中间版本未丢文件或被错误覆盖。例如某次路径映射错误删除文件，后续提交恢复它，现有六项检查仍可能全部通过。“D/R 自动消解”也未区分同一文件改名映射后的冗余删除与两个不同文件真正撞名。请明确真实路径冲突的拒绝策略，并逐提交核对变换后的树（包括路径、内容和文件模式）；增加中间提交损坏但 tip 正常、真实路径碰撞及 verify 必须拒绝的反例。
- [major] R-03 钩子验收缺少核心扫描边界和失败路径。
  - 详情:定位：plan.md:69、73–79、172–174。TC-02 的 pre-push 仅验证敏感提交信息和干净推送，没有验证文件内容、文件路径、较早提交泄露但 tip 已清理、远端旧 id 本地不存在的明确新增分支，以及推送二进制的拦截与放行；pre-commit 也没有暂存区含敏感内容而工作树已清理的场景。fail-closed 只验规则文件缺失，未验无 python3、规则不可读或格式/正则错误。请补充这些 A 档断言，明确失败时非零退出、不得静默跳过检查；否则现有测试通过仍不能证明两个入库闸门有效。
- [major] R-04 实际生产截图的脱敏及原证据可用性没有验收项。
  - 详情:定位：plan.md:43–44、98–99、172–180。交付明确要求遮住真实名称并保留徽标和菜单，但 TC-03 只测合成二进制替换，TC-04 的文本零命中和 TC-05 的一致性检查均不能证明实际 PNG 已正确打码。请增加实际替换文件与已审核私有资源一致的 A 档检查；视觉遮盖是否完整、原版面结论是否仍可见，如确需人工判断，应另列 C 档，写明不可自动化理由，并提供结果陈述及文件/处理位置锚点，不能只交截图。
- [minor] R-05 多条验收命令的脚本相对路径与仓库根工作目录不一致。
  - 详情:定位：plan.md:176–180。辅助脚本应位于本任务 evidence/，但命令写为 bash evidence/*.sh；其他用例的 .venv、apps 等路径又要求从仓库根执行。evidence.sh 会继承调用者的 cwd，不会切换到任务目录。请统一声明从仓库根执行，并将这些辅助脚本写成完整的任务相对路径。
- [minor] R-06 实际提交和强推步骤漏写已定义的二进制放行方式。
  - 详情:定位：plan.md:69、98、116–119、163。当前脱敏提交会修改 PNG，历史强推也会包含二进制文件，按新钩子的默认规则均会被拦截。方案已明确人工审核后可用 DOPILOT_REDACTION_ALLOW_BINARY=1 放行，意图清楚；请在相应执行步骤中补上审核条件和单次命令环境变量，避免按步骤执行时中断。
- [minor] R-07 “现有 rawf-evidence v1 不受影响”的表述不准确。
  - 详情:定位：plan.md:197–198。现有升级任务的 TC-03.log:6 等证据头含本仓库旧 git_head，按历史 ID 映射规则仍会改写；不含业务词不等于文件不变。请区分正文脱敏与头部 ID 映射，说明等长映射不改变正文 bytes，并在历史试跑后复核 v1 格式仍有效。
- [minor] R-08 docs/README.md 的历史只增不改约定遗漏同步例外。
  - 详情:定位：plan.md:83–92、151；docs/README.md:8–9。方案更新 AGENTS.md 的脱敏例外，但 docs/README.md 仍无条件声明 .ai/ 历史只增不改。请同步引用新决策及脱敏例外，保持持久文档与新规则一致。
