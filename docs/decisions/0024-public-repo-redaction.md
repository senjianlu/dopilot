# 0024:公开仓库信息脱敏——业务词只存私有规则,钩子拦截提交与推送,公开历史已改写

- 日期:2026-11-02
- 背景:本仓库在 GitHub 公开。`.ai/` 的方案、调查报告与证据多取自生产环境,
  2026-11-02 盘点时当前树 48 个文件命中 3,088 处业务信息:正在采集的目标站点与
  数据源(调度名、域名、接口)、下游爬虫仓库与业务品牌、爬虫内部的模块/类/表/
  函数名、游戏 appid 与商品名、生产域名/主机名/内网 IP,以及整份的生产原始数据
  (系统 journal、服务端与爬虫日志、Redis 转储、监控时序、生产 compose、带真实
  调度名的截图);另有一份证据把疑似真实的 agent token 与 Redis 密码前缀原样
  打印。全部 67 个历史提交同样可见,其中 5 条提交信息含站点名或业务名。
- 决定:
  1. **不得进入仓库(含提交信息、文件名、截图)的六类信息**:
     ① 目标站点与数据源:名称、品牌缩写、域名、接口路径、调度名中的站点段;
     ② 下游项目与业务:爬虫/处理仓库名、业务品牌与其域名,爬虫内部的模块、
        类、表、函数、Redis 键名;
     ③ 业务对象:跟在调度名里的游戏 appid、商品/礼品卡名、币种组合等;
     ④ 生产基础设施:公网域名、主机名、内网 IP 与内网域名(通用工具名如
        Tailscale/Prometheus、手册约定的 `/opt/dopilot` 等路径不在此列);
     ⑤ 凭据:任何真实 token/密码/密钥,**包括其任意前缀**(检测脚本的自测
        也只能用合成值);
     ⑥ 原始生产数据:journal、原始日志、DB/Redis 转储、API 快照、监控时序、
        生产配置文件、生产截图——即使替换了名称,频率、量级、报错原文仍构成
        业务画像。
  2. **证据怎么写**:原始数据只放维护者本机私有目录(建议
     `~/.local/share/dopilot-private/<日期>/<任务>/`),仓库里只放结论、聚合
     统计与脱敏摘录;要入库的命令输出先经
     `python3 scripts/redaction/redact.py apply -` 过滤;A 档证据命令不得直接
     打印原始生产数据;截图先打码,二进制入库前须人工确认
     (`DOPILOT_REDACTION_ALLOW_BINARY=1`)。
  3. **别名约定**:站点 `site-xx`(字母随机分配,不按字母序,防反推);appid
     `g1`…;下游爬虫 `crawler-a`;业务 `biz`;主机 `console-host` /
     `agent-host-NN`;内网 IP → `192.0.2.0/24`(RFC 5737 文档段);域名 →
     `example.com` / `internal.example`。**别名对照只存在私有规则文件里**,
     不得写进仓库。
  4. **机制**:
     - 私有规则文件(业务词 → 别名,另含说明桩与二进制替换规则)默认
       `~/.config/dopilot/redaction-rules.tsv`(权限 600),可用
       `DOPILOT_REDACTION_RULES` 指向别处;格式见
       `scripts/redaction/redact.py` 文档串。新接入的数据源**先登记规则再
       写证据**。
     - 入库的 `scripts/redaction/generic-rules.tsv` 只含通用规则(内网 IPv4、
       内网主机域名),兜底未登记的地址。
     - `.githooks/pre-commit` 扫描暂存区内容与路径;`.githooks/pre-push` 扫描
       待推引用名、附注标签说明,以及远端尚无的每个提交的提交信息、改动文件与
       路径(合并提交对每个父提交都比较;文件类型变更与符号链接按链接目标扫描);
       匹配 `stub` 规则的路径只接受原样的说明桩内容,原始数据即使不含登记词
       也会被拦下。私有或通用规则文件缺失/不可读/格式错误、无 python3 时一律**拦截**
       (fail-closed);外部贡献者设 `DOPILOT_REDACTION_RULES=none` 有意只跑
       通用规则。二进制文件无法扫描,默认拦截,人工看过后以单次环境变量
       `DOPILOT_REDACTION_ALLOW_BINARY=1` 放行。
     - 本身敏感的内容一律写成可检测的规则(`lit` / `re`);只改写不检测的
       `rewrite` 规则仅用于修饰性调整。
  5. **`.ai/` 只增不改的例外**:历史任务文件允许做脱敏改写,但只能经
     `redact.py`(或按本决策手工打码截图),不得借机改动结论、轮次或结果。
     脱敏后的旧证据不再是逐字节原始输出,这是有意的取舍。
  6. **历史**:本决策随当前树脱敏一并提交;随后于 2026-11-02 用
     `scripts/redaction/rewrite_history.py` 按同一规则改写了公开历史
     (`master`,即远端唯一的公开引用),逐提交核验通过并**经维护者确认**后
     强推。改写要求:提交结构、作者与时间不变;原始数据文件在所有历史版本中
     换为说明桩;文件内容与提交信息中对本仓库提交 id 的引用映射为新 id(避免
     凭旧 id 找到托管方仍保留的未脱敏悬空提交);新旧 id 对照与改写前的完整
     备份只保存在维护者本机私有目录。实施结果与核验统计记录在
     `.ai/2026-11-02/public-repo-redaction/` 的 `history-rewrite.md`。日后再
     发现泄露,同法处理,强推须用户确认。
  7. 被否备选:删除整个 `.ai/` 历史证据(丢掉过程痕迹,且问题在于写法而非
     目录本身);仓库转私有(违背开源);只改当前树不改历史(历史照样可见);
     词表入库(词表本身就是泄露);原始数据只做别名替换、保留原文件(业务画像
     仍在,2026-11-02 用户裁决换为说明桩)。
- 影响:
  - 维护者新机器须先放置私有规则文件,否则提交与推送被拦;该文件丢失即失去
    检测能力,应另行备份(不进任何仓库)。
  - 两个钩子位于模板"可整体替换"目录 `.githooks/`,登记为
    [`0020`](0020-ai-workflow-template-version-anchor.md) 的有意偏离 D-7,升级时须保留。
  - AGENTS.md 通用硬规则新增"公开仓库脱敏";`.ai/` 只增不改加注本例外。
  - 已知外部残留(仓库之外,无法由本仓库操作消除):托管方在垃圾回收前仍可按
    完整 id 访问改写前的悬空提交,公共事件流保留近 90 天的推送记录(含提交
    信息);已发布的旧镜像内含改写前的测试夹具;同作者的模板仓库
    `ai-workflow-template` 含少量同类词。
  - 实施记录:`.ai/2026-11-02/public-repo-redaction/`。
